# Avatar Image Caching via Nuke Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cache GitHub avatar images (memory + HTTP disk cache, with request coalescing) by replacing `AsyncImage` with NukeUI's `LazyImage` in the single `AvatarView` chokepoint.

**Architecture:** Add the Nuke Swift Package and link its `NukeUI` product to the PRTracker target by hand-editing `project.pbxproj` (modeled exactly on the existing Sparkle wiring), let `xcodebuild` resolve and pin it, then swap the one `AsyncImage` call in `AvatarView` for `LazyImage` using Nuke's default shared `ImagePipeline`. No custom pipeline, no call-site changes.

**Tech Stack:** SwiftUI (macOS 26.4, Swift 5), Swift Package Manager, Nuke / NukeUI 12.x.

**Spec:** `docs/superpowers/specs/2026-06-05-nuke-image-caching-design.md`

## Task 2: Use LazyImage in AvatarView

- [ ] **Step 1: Add the NukeUI import**

```swift

```
to:
```swift
import SwiftUI

```

- [ ] **Step 2: Replace AsyncImage with LazyImage**

Find (line 10–11):
```swift
                AsyncImage(url: url) { img in img.resizable() } placeholder: { Color.clear }
                    .clipShape(Circle())
```
Replace with:
```swift
                LazyImage(url: url) { state in
                    if let image = state.image {
                        image.resizable().scaledToFill()
                    } else {
                        Color.clear
                    }
                }
                .clipShape(Circle())
```

The surrounding `ZStack` (with the `Circle().fill(Tokens.commented)` behind), the `.frame(width: size, height: size)`, and the `else` letter-fallback branch are unchanged.

## Done

`AvatarView` loads avatars through NukeUI's `LazyImage` on Nuke's shared `ImagePipeline`: repeated avatars are served from the in-memory `ImageCache`, concurrent loads of the same URL are coalesced, and HTTP disk caching via `URLCache` gives cross-launch persistence — replacing the per-instance, uncached `AsyncImage`.
